## 1. Overview

The **VoiceBack PWA** is an accessible, role-gated healthcare frontend built with React 19 and Vite. Designed specifically for aphasia patients, speech therapists, and caregivers, the application delivers:

1. **Patient Communication Hub:**
   - Automatic microphone selection (BLE connected → INMP441; BLE disconnected → Browser mic).
   - Integration with ElevenLabs Scribe STT for phonetic transcription.
   - Dynamic meaning reconstruction and Companion Mode ephemeral response choices generated by the Gemini Context Engine.
   - Explicit patient confirmation UI (Confirm / Change / Cancel). Cancel prevents TTS.
   - High-fidelity voice playback utilizing the patient's mapped Cartesia cloned voice.
2. **Web Bluetooth Audio Bridge:**
   - Connects directly to the ESP32 smart neckband (`VoiceBack-Neckband`) via Web Bluetooth GATT.
   - **Upstream:** Receives raw 16kHz audio from the INMP441 microphone over BLE for STT processing.
   - **Downstream:** Decodes synthesized Cartesia audio, resamples to 16kHz 16-bit Mono PCM, and streams chunks to the ESP32 for physical speaker playback.
3. **Clinical Role-Based Portals:**
   - **Patient Portal:** Single-setup persistent authentication, speech exercise modules, emergency SOS trigger, and dynamic conversation cards.
   - **Doctor Portal:** Clinical session tracking, patient progress analytics, and appointment management.
   - **Caregiver Portal:** Live patient monitoring, emergency alerts, and contextual communication prompts.

> **Note:** The current architecture uses NO BioAmp telemetry, NO EMG, and no manual microphone switching. Both the INMP441 and browser microphone seamlessly feed the identical downstream pipeline.

## 3. Web Bluetooth (BLE) Architecture (`deviceService.js`)

The PWA connects to the ESP32 neckband over Web Bluetooth:
- **Device Advertised Name:** `VoiceBack-Neckband`
- **Primary Service UUID:** `4fa8c001-1278-472e-b997-63992e716a4d`

### Bi-Directional Audio Streaming Pipeline:
1. **Microphone Capture (Upstream):** When BLE is connected, `UniversalSpeechInput.jsx` automatically uses the `MIC_AUDIO` notification characteristic to receive 16kHz audio from the ESP32's INMP441 microphone and routes it to ElevenLabs Scribe STT.
2. **Audio Playback (Downstream):**
   - Receives Cartesia synthesized audio buffer from the backend.
   - Decodes audio into raw buffer via browser `AudioContext`.
   - Resamples to **16,000 Hz 16-bit Mono PCM** using `OfflineAudioContext`.
   - Streams chunks sequentially to the ESP32 audio characteristic (`cba1483e-36e1-4688-b7f5-ea07361b26b9`), which transfers them directly to the MAX98357A I2S DAC.

## 4. Voice Cloning & Language Guidelines

- **Cartesia TTS Integration:** Patients enroll voice samples via `VoiceCloningModule.jsx`. The assigned `voiceId` is stored in MongoDB `VoiceProfile` and reused for all subsequent speech output. The frontend never exposes Cartesia API keys or hardcodes Voice IDs.
- **Language Support:** VoiceBack reliably supports the native language spaces it processes (e.g., Kannada input yields Kannada output, English yields English, and mixed input yields mixed natural output). 
- **Offline/Failure Fallback:** If cloud synthesis is unreachable, `voiceService.js` falls back to browser native SpeechSynthesis API to ensure patients always have a voice.
